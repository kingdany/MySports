# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

MySports is an ad-free sports calendar. There is no server: a C# importer runs on a GitHub Actions cron every 3 hours and publishes static JSON to GitHub Pages, and the Expo app reads those files.

```
GitHub Actions (cron) → MySports.Importer (C#) → JSON → gh-pages branch → GitHub Pages → app
```

F1, MotoGP, Serie A, Champions League, Europa League and Conference League are implemented. Other football competitions are planned (see "Prossimi passi" in `README.md`).

Code comments, UI strings, log messages, docs and commit messages are in Italian (commits use the imperative, e.g. "Aggiungi le classifiche piloti e costruttori"). Keep to this.

## Commands

The repo has no automated tests.

Importer (.NET 10), run from the repo root because `.env` is read relative to the working directory:

```
dotnet build MySports.slnx
dotnet run --project src/MySports.Importer -- --out out                                      # current season, feeds and meta
dotnet run --project src/MySports.Importer -- --competition f1 --seasons 1950-2025 --out out # past seasons (also "2019,2021")
dotnet run --project src/MySports.Importer -- --competition f1 --seasons 1950-2025 --standings-only --out out
dotnet run --project src/MySports.Importer -- --competition serie-a --seasons 2024-25,2025-26 --out out # football seasons are listed by name
dotnet run --project src/MySports.Importer -- --recover-videos --out out                     # also look for old matches' videos; with --seasons, in those seasons
```

What is still missing from past seasons (videos per channel, match details) is tracked in `docs/STATO-IMPORTAZIONI.md`, not in the README todo. After checking an import, run `node tools/stato-importazioni.mjs` (published data; pass a folder such as `site` for local output) to refresh its tables, and update its handwritten notes; the script only rewrites the part between its markers.

These commands only write locally. To publish past seasons, run the "Aggiorna dati" workflow manually, which takes the same options as inputs. Jolpica allows about 500 requests an hour, so long imports stop and wait for the limit to reset.

App (run from `app/`):

```
npm install
npx expo start           # add --tunnel if the phone is not on the same Wi-Fi
npx expo lint
npx tsc --noEmit
npx expo install <pkg>   # always use this to add packages, so versions match the SDK
```

## Architecture

### Importer (`src/MySports.Importer`)

- **The output folder is also the input.** Each run loads the existing season file and merges it with the fresh data. Sources don't provide videos, so videos are kept from the previous run. Results missing from this run are also kept (e.g. OpenF1 is down), and so are standings if fetching them fails. This is why CI checks out `gh-pages` into `site/` and runs with `--out site`.
- **Event IDs must stay stable** (`f1-{season}-{round}-{session}`, `serie-a-{season}-{matchId}`), because the merge matches on them and the app routes on them. They must also be unique within a season, since the merge builds a dictionary from them and throws on duplicates.
- **Partial failure is expected.** A failing source or season is logged and the run exits with code 1, but the workflow still publishes whatever was saved. Previously published data is reused for the feeds.
- **Adding a competition:** implement `IEventSource` and add it to the `sources` array in `Program.cs`. `meta.json` lists a competition only if its current-season file exists, and its available seasons come from the files in its output folder.
- **F1 uses two sources.** `JolpicaF1Source` is the primary one and uses `OpenF1Client` for official session times (Jolpica can miss rescheduled sessions) and for sprint qualifying results. OpenF1 is only queried from the 2023 season on, and if it fails the importer carries on with Jolpica data alone. Team colours (`teamColor` on classification and standing rows) come from Italian Wikipedia (`WikipediaF1Colors`), which the user prefers to OpenF1's: the "Campionato mondiale di Formula 1 {year}" page's driver table, background of each race number cell, read as raw wikitext (`action=raw`, since the API's anonymous limits are tight). The table is handwritten and varies by year, so the parser only looks for coloured number cells in the table whose header has "Costruttore" and "Pilot…", plus the driver link that follows (named colours like `white` included, a `rowspan` number covers several drivers). Colours exist from 1983. Wikipedia gives them per driver and names teams differently from Jolpica, so each Jolpica constructor takes the colour most frequent across its drivers' race results (matched by surname, and given name when two share it); a driver who changed team counts less than the teammates who stayed. A driver's standing row takes the colour of the team of their last race. If Wikipedia fails the season has no colours. Use `HttpJson` for HTTP calls: it handles 429 and transient retries, and hides API keys in error messages.
- **MotoGP uses `MotoGpSource`**, built on the public but undocumented API behind motogp.com (`api.motogp.pulselive.com`, no key). Session times come from the calendar (`/events`), because the results archive (`/results`) has provisional future session dates and local times labelled as UTC; classifications and rider standings (the only standings the API has) come from the archive, linked to the calendar through `toad_api_uuid`. The round is counted in date order among the GPs the premier class raced, because the calendar's `sequence` has duplicates and gaps in past seasons. Seasons go back to 1949: the premier class is "500cc" in the archive until 2001 (same `MGP` code in the calendar). Before 2001 (`FirstSeasonWithTimes`) the calendar's times are placeholders, so events are `dateOnly`. Qualifying is one `qualifying` event: from 2013 Q1 and Q2 merged in grid order (Q2, then the rest of Q1) with `q1`/`q2` times; 2005–2012 a single `QP` session with the time in `q1`; earlier QP1/QP2 have no classifications. Old seasons have no team (the bike is used instead) and 0 points in race classifications (left out), and some races have an empty classification in the archive itself. Team colours exist only from 2026 and only from `HandTeamColors`, written by hand from the MotoGP "Iscritti" table on it.wikipedia.org/wiki/Motomondiale_{year} (background of the race number cell). The user chose no colours rather than wrong ones: older pages there and en.wikipedia (whose backgrounds mark replacements and wildcards) have no team colours, and the site's team list (`/teams`) is mostly a placeholder grey or wrong, so don't add it or constructor colours back as a fallback. Rows match a part of the team name, since sponsors change it ("LCR", "Tech3"), and are valid from a season until a newer row for the same team; a team without a row has no colour. Pre-qualifying and warm-up are saved as `practice` and `warm_up`, FP4 (2015–2022) as `fp4`, all hidden in the app like F1 practice. A restarted race also has `RAC2`/`SPR2`: it stays the same event and takes the last start's classification. Cancelled sessions get `Cancelled`. GPs whose calendar times are wrong in the source itself are fixed in `TimeCorrections` (Jerez 2024: everything 2 hours late).
- **Football uses `FootballDataSource`** (football-data.org, `FOOTBALL_DATA_API_KEY`). It has its own `HttpClient` so the key is only sent to that API. The free plan allows 10 requests a minute and seasons from 2023-24 on. Season names are `2026-27` and roll over on 1 August. Matches without a confirmed kickoff come back at 00:00 UTC on a provisional date, so they are saved as `dateOnly`. Scores are kept only for finished matches, because the 3-hour cron would leave partial scores stale. Standings include a `scorers` table with at least 10 names, completing the last tied group, so it can have more rows. Tied players share a number with no gaps (1, 2, 2, 3). Its `points` field holds the goals. To add it to past seasons use `--standings-only`. Table rows get a `zone` (Champions, Europa, Conference, relegation) from position rules, because the API has none: `SerieAZones` by default, `SerieAZoneExceptions` for seasons whose actual European places were different. The app only draws them. The Champions League (`champions-league`, from 2024-25 because the API merges the 2023-24 groups into one table) uses `ChampionsLeagueZones`. Knockout matches set `stage`, with `round` 1/2 for the two legs; a team not yet known is left out and the title says "Da definire". The API's `fullTime` includes shootout goals, so they are subtracted and saved as `homePenalties`/`awayPenalties`.
- **Football from ESPN** (`EspnFootballSource`), for competitions football-data's free plan lacks: the Europa League (`europa-league`, ESPN league `uefa.europa`) and the Conference League (`conference-league`, `uefa.europa.conf`), both from 2024-25 like the Champions League, because earlier seasons had groups the app doesn't handle. Same public API as match details, no key, no quota, and its `HttpClient` (`EspnMatchDetails.Http`). `scoreboard?dates={year}&limit=1000` returns a whole calendar year (a date range returns nothing), so a season is two calls filtered on `season.year` (the start year); qualifiers aren't there. Knockout stages come from `season.slug`, legs from `leg`, shootouts from `shootoutScore` (not in the score); league-phase matchdays aren't given, so they are counted as groups of match days more than 3 days apart. `timeValid: false` means `dateOnly`. Standings are saved only when ESPN has a single table; scorers come from `statistics` (`goalsLeaders`), with the team's short name taken from the standings, and the 10-names-plus-ties rule shared with football-data (`FootballDataSource.ScorerRows`). Team ids are ESPN's with an `espn-` prefix, so they never match football-data's: the app matches teams across competitions by name, which is why `ShortNames` turns "AS Roma" into football-data's "Roma" (Lazio, Bologna, Milan and Juventus already match), expands ESPN's abbreviations ("Spurs", "C Palace"), drops prefixes Italian doesn't use ("FC Porto", "SK Brann") and reuses the Italian names of the Champions League (Stoccarda, Slavia Praga); other names Sky writes in Italian ("Nizza", "Lione") are `TeamAliases` in `YouTubeHighlights`, as for the Champions League. The league phase uses `ChampionsLeagueZones`. Europa League and Conference League teams have the names the user listed (Italian where Italian has one: "Lione", "Magonza", "Legia Varsavia", "Universitatea Craiova"; otherwise the local spelling with its diacritics: "Jagiellonia Białystok", "Ħamrun Spartans", "Viktoria Plzeň"), and football-data's `ShortNames` give the same name to the clubs that also played the Champions League ("Bayer Leverkusen", "Marsiglia", "Salisburgo", "Copenaghen", "Manchester United"...), so the team filter finds them in every competition. Only the short name changes: the full `name` stays the source's, which match details use to find ESPN's match. Letters that `Plain` doesn't strip (ł, ð, Ħ, Š) need an alias for the titles that write them without.
- **Match details** (`EspnMatchDetails`) come from ESPN's public, undocumented API (no key, own `HttpClient` with gzip decompression), for Serie A (`ita.1`), the Champions League (`uefa.champions`), the Europa League (`uefa.europa`) and the Conference League (`uefa.europa.conf`; these two already come from ESPN but go through the same day/score/name matching), in the normal run and in `--seasons` imports (not `--standings-only`; ESPN has seasons from 2023-24 and no quota). For finished matches without `details`: one `scoreboard?dates=` call per match day (date ranges return nothing), matched on day and score, then on team names sharing a word (accents and words like "FC" ignored; `TeamAliases` only for the few with nothing in common, e.g. Red Star Belgrade / Crvena Zvezda), because football-data's `shortName` is Italian ("Lipsia") and ESPN's names are English; an ESPN match is never used twice. Then one `summary` call per match. Only structured fields are kept: goals (`penalty`, `ownGoal`; an own goal's `side` is the team credited with it, ESPN's own convention), missed and saved penalties (both `missedPenalty`), cards (a second yellow is a plain `red-card` that only the text "Second yellow card to..." identifies), starters with shirt numbers, substitutions (first participant comes in, second goes out). Shootout events are dropped. If ESPN's goals don't add up to football-data's score the match is skipped and retried next run (ESPN can lag right after full time). Details are kept from the previous run like videos, unless their `version` differs from `CurrentVersion`: bump it whenever the saved fields change, so the next run re-downloads every match once (the old details stay if the download fails). Player names are saved in full plus `short`, ESPN's `lastName` (compound surnames included), left out when equal to the full name (players known by one name, e.g. "Bremer").
- **Highlights** (`YouTubeHighlights`) are attached to the current season, or to past seasons with `--recover-videos`, and are skipped if `YOUTUBE_API_KEY` is not set. Each session gets one video (`videoSources` in `Program.cs`, channels in order of preference): Serie A takes DAZN, then Sky for matches without a DAZN video, then the official Serie A channel (its rule needs "Home-Away" followed by "| HIGHLIGHTS |", so extended, cinematic and classic highlights are left out, and only the Italian version, whose "Serie A" is followed by the sponsor while the English one has the year straight after; it is the only Serie A channel whose videos can be embedded); F1 takes Sky, then the official English channel; Champions League takes Sky, then Prime Video (which only has the Wednesday match it broadcasts), then Sky Video; Europa League and Conference League take Sky, which publishes almost only the Italian teams' matches on YouTube (same title rule as the Champions League, `SkyCupTitle`), then Sky Video; MotoGP takes Sky. A channel only searches sessions that have no video from a channel before it, and a video from a preferred channel published later replaces the fallback one. Every run drops saved videos whose channel is no longer used or that no longer belong to their session (`YouTubeHighlights.Matches`: the title must pass the channel's rule and the session must be the one `SessionFor` would pick today, i.e. the latest finished session the title matches that started up to 3 days before publication), so fixing a rule or a session time also removes the wrong videos it had picked; videos dropped from old sessions only come back with `--recover-videos`. Each channel has its own title rule: F1 and MotoGP videos match by session type and publish date, not GP name; football videos match by home and away team (`shortName`, so a renamed team must match how channels write it; `TeamAliases` covers titles that use another name, and accents are ignored) and publish date. DAZN titles put free text before the teams, so its rule looks for "Home-Away" followed by the score (or "Highlights" in the title) instead of extracting names. A video is looked for only during the 3 days after its session, so a session left without one no longer lengthens every run's read of the channel's uploads. To fill in older sessions (a new competition or title rule, past seasons) run with `--recover-videos`, which is a manual option because it reads the channels far back. The uploads playlist only returns a channel's latest 20,000 videos (DAZN reaches November 2024, Sky Sport September 2024), so when it stops at that limit the recovery searches the older sessions' windows with `search.list` (`SearchBeforeAsync`: no keywords, since they made it miss videos; `regionCode=IT`, since GitHub runners are in the US and Italy-only videos would be left out; 3-day periods; a separate daily quota, "Search Queries per day"). Period searches don't return every video of the period, nor the same ones each time (Roma-Inter 2023-24 was missed by two full recoveries), so a window with at most `MaxTargetedSessions` football matches still waiting is searched match by match instead, with the two teams as keywords (short names, then an alias), which found it; these targeted searches run before the periods so they get the quota first, and windows with more matches (a season recovered for the first time) still use periods, which cost less there. It is capped at `SearchBudget` pages per run for all channels together; past the cap it saves what it found and the next recovery carries on. A 404 (`playlistNotFound`) on a later uploads page is a transient YouTube error: the page is retried, then the read stops at what it has, so the channel isn't lost; no search runs after such a partial read. Videos blocked in Italy are dropped. To tell why a session has no video, each channel logs how far it read the uploads (and why it stopped), uploads out of date order, videos whose title passes the rule but were rejected near a waiting session (published before the start, past 3 days, other year in the title), videos no longer available or blocked, and the sessions still without a video. Videos that can't be embedded are saved with `embeddable: false`, and the app opens them directly in YouTube.
- **Sky Video** (`SkyVideoHighlights`, source name "Sky Video") is the last video source of the three cups: the site video.sky.it has many more matches' highlights (short clips, mostly the goals; for the Europa League 2025-26 almost all, in the Conference League and in 2024-25 only some matchdays, the others only in "all the goals" compilations that match no match), while Sky's YouTube channel has almost only the Italian teams'. Sources share `IHighlightsSource`, so it goes through the same chain, `Matches` check and `--recover-videos` as the channels, reusing their title rules and `TeamAliases` (the titles are the same as on Sky's channel; the site's own spellings, typos included, are aliases too) and `YouTubeHighlights.SessionFor`. There is no documented API: a section page (`/sport/calcio/europa-league`, then `?pag=2`...) is a Next.js page whose `__NEXT_DATA__` JSON holds its 16 videos newest first (`subSubsectionPage.videoList`: title, `publication_date` in Italian time, `video_still`, `duration`, `page_url`); pages are read one a second until the oldest waiting session, and a missing JSON on the first page is an error (the site changed). The sitemaps stopped in January 2026 and `/api/` is excluded by robots.txt, the section pages aren't. The videos can't be embedded (`no_embedded`), so they are saved with `url` and `embeddable: false`, and the app opens the page with `expo-web-browser`. It doesn't need a key but is still skipped without `YOUTUBE_API_KEY`, because with it alone in the chain the saved YouTube videos of the cups would be dropped as coming from an unused source. Its log lists titles that pass the rule but match no match in the period searched (usually a name to add to the aliases).

API keys come from `.env` locally (gitignored) and from Actions secrets in CI.

### Data contract

`app/lib/types.ts` is a hand-written mirror of the C# records in `src/MySports.Importer/Models` and `JsonPublisher`'s file records. There is no codegen, so change both sides together. Serialization uses camelCase and omits nulls, so nullable C# fields are optional in TypeScript. Season files already published on `gh-pages` may predate newer fields (e.g. `standings`, video `source`/`duration`/`url`), so new fields must be nullable or have a default. This matters on the importer side too: it reads those files back through the same records, so a new `required` property makes the load fail and that season's import errors out.

Old F1 seasons have no session times and football matches may not have a kickoff yet: those events set `dateOnly` and use 12:00 UTC as `startsAt`, so the date stays the same in every time zone.

### App (`app/`)

- Routes use Expo Router and live in `app/app/`, not `src/app/` as `app/AGENTS.md` says. Shared code is imported with the `@/` alias.
- `lib/data.tsx` (`EventsProvider`/`useEvents`) is the single data layer. It loads `meta.json` and every competition's current season at startup; past seasons download on demand and stay in memory. `getEvent` only searches seasons already loaded, so a past-season event route shows "Evento non trovato" until that season has been loaded.
- The app does not read `upcoming.json` or `results.json`, even though the importer publishes them. Screens filter the current-season events themselves: with one competition chosen the Prossimi tab shows the rest of the season, while "Tutti" and a sport's "Tutte" are limited to the next 30 days (`ALL_DAYS` in `app/(tabs)/index.tsx`) so the list doesn't grow with every competition added.
- `CompetitionBar` has two rows, the same in all three tabs: sports on top (`lib/sports.ts` groups competitions by `meta.json`'s `sport`: Calcio = `football`, Motori = `motorsport`, i.e. F1 and MotoGP; an unknown sport goes last, named by its id), then the chosen sport's competitions in smaller chips, only when it has more than one. Prossimi adds "Tutti" on top and "Tutte" below; tapping a sport there starts from its "Tutte" (or straight from its competition, if it has only one). Sport icons are Material Symbols paths drawn with `react-native-svg` (`components/SportIcon.tsx`): the ball, and the helmet (`sports_motorsports`) for Motori, which the user chose over the chequered flag (`sports_score`) after comparing them; a wheel was rejected. Competition chips keep the 132×36 size of the old single row, because at 32 high "Champions League" on two lines was hard to read.
- Risultati and Classifiche never mix competitions. They share one choice from `CompetitionBar` through `useCompetitionSeason` (`lib/useSelectedSeason.ts`), defaulting to the first competition in `meta.json`; the sport row shows the chosen competition's sport, and tapping another sport goes back to the last competition chosen in it (`competitionBySport`), or its first. `SeasonPicker` only lists that competition's seasons, and the season goes back to the current one when the competition changes.
- `lib/preferences.tsx` saves the competition choices on the phone with AsyncStorage. Prossimi has its own choice, separate from the other two tabs: `null` for "Tutti" (the default), `sport:<id>` for a sport's "Tutte", or a competition id (`upcomingChoice` in `lib/sports.ts` reads it back).
- Switching competition or season uses `useDeferredValue`: the buttons update first with the screen in its loading state, then the list renders. `EventList` and `EventRow` are memoized and their props are kept stable, so unrelated changes don't redraw the mounted rows.
- Classifiche also shows a "Tabellone" (`lib/bracket.ts`, `components/Bracket.tsx`) when a season has knockout matches. It is not published data: the app builds it from the events' `stage`, summing the legs and using penalties for the winner. It is a tree scrolled sideways that shows who goes through, without scores, since results and videos live in Risultati. Ties are linked through the winners, because the API has no bracket positions: rounds not yet known are not drawn, and matches with a team not yet known are skipped.
- Prossimi and Risultati also have a team filter (`useTeamFilter`, `TeamPicker`), built from the teams in the events on screen, so it doesn't appear for F1, MotoGP or "Tutti"; it does for football's "Tutte" (a team across Serie A and the cups). Teams are matched by `teamLabel`, not id, because football-data and ESPN give the same club different ids. Each tab keeps its own choice in memory only. With a sport's "Tutte" the teams are too many to list (they grow with every competition), so the picker is `searchable` (`PickerBar`'s `search`): with an empty field it shows only "Tutte le squadre" (removes the filter, so it appears only when a team is chosen; alone above the empty field "Tutte" looked like a second "Chiudi") and the last 5 teams chosen there (`recentTeams` in `lib/preferences.tsx`, saved on the phone, only those present in the list), plus a hint with a magnifier saying the others can be searched (bigger when there are no recent teams yet, as on first use); typing shows the teams whose name, or full source name, contains the text anywhere, accents and case ignored, those starting with it first. With a single competition (and in Risultati) the full list stays, one team per row (`PickerBar`'s `rows`), with "Tutte le squadre" always first.
- Prossimi's rows don't open the event detail (`linked={false}`). Risultati's do.
- Competition logos are SVG strings in `constants/CompetitionLogos.ts`, drawn by `CompetitionLogo` with `SvgXml`. They are used exactly as on Wikimedia Commons, "TM" included where the file has it (F1 yes, MotoGP no; never add one), and the Serie A logo only loses its sponsor box. Monochrome parts use `currentColor`, so the dark theme can recolour them; `mono` turns every fill white for the coloured badges (event rows, event detail) and the active chip in `CompetitionBar`, except `plate` logos (Serie A, unreadable in one colour), which keep their colours on a small white plate. In event rows a logo that isn't enough on its own gets its `rowLabel` next to it ("Serie A" by the plate, "UCL" by the Champions League ball, "UEL" by the Europa League trophy, cut by the user's choice from "Europa League 2021.svg", whose lettering and ™ were unreadable at the app's sizes, "UECL" by the Conference League trophy with its green arcs, cut the same way from "UEFA Conference League full logo (2024 version).svg" (the file without "full" has only the lettering); the rows' left column is 72 wide for them). F1 and MotoGP are `wordmark`s, so their name label is left out next to the logo. `CompetitionBar` shows the competition's full `name` from `meta.json` (the user finds "Champions" reads like an abbreviation), and the chips of each row all have the same width, so no competition looks more important: F1 and MotoGP are capped to the same logo width, and long names ("Champions League") go on two smaller lines. `competitionLabel` (`lib/format.ts`) also says "Champions League", used in the event detail badge. A competition without a logo falls back to its text label; adding one means adding its SVG there (with fills as attributes, since `SvgXml` ignores `<style>` classes).
- The event detail header (badge, title or scoreboard, date, place) is centred for every event; F1/MotoGP classifications below stay left-aligned.
- F1 and MotoGP rows (Classifiche and the event detail's classification) show `teamColor` as a bar between position and name (`TeamColorBar`). It is drawn only when some row of that list has a colour, and rows without one keep the empty space so names stay aligned. Colours close to the theme's background (white, black: Haas, Cadillac, LCR) get a thin border.
- Football crests come from the events' `logoUrl` (football-data PNGs) and are drawn by `TeamLogo` with `expo-image` (disk cache, `recyclingKey` for list rows); without a crest, or if it fails to load, it shows the team's initial in a circle of the same size. In the dark theme every crest sits in a light circle (the image can't tell whether a crest is dark, and dark ones like Juventus would vanish on black). They appear in event rows, the scoreboard, lineups, standings, the bracket and the team picker. Standing rows have only the team name, so `teamLogos` (`lib/useTeamFilter.ts`) maps `teamLabel` to the crest from the same season's events.
- The event detail shows a football match's `details` (`components/MatchDetails.tsx`): `MatchTimeline` under the score (home events left, away right, minute in the middle) and `MatchLineups` after the video. Cards are drawn with Views; the ball (struck through in red for a missed penalty) and the substitution arrows are `react-native-svg` paths copied from Material Symbols, not `expo-symbols`, whose Android rendering is a font glyph that got clipped and sat lower than the cards. Players show by surname; tapping one shows the full name in a toast (`components/FullNameToast.tsx`, wrapped around the screen outside the ScrollView, `useShowFullName` to show it). Classifiche uses the same toast: tapping a row shows the full name (with the team for drivers and scorers), and tapping a team in the bracket shows the same name as the standings (`teamLabel`, not the source's official name), untruncated. Football matches get a centered scoreboard (home, score, away) instead of the title.
- `EventList` sets a very large `windowSize` so rows stay mounted, as a fix for scrolling that jumps up and down once the list starts unmounting its first rows (about 10 screens down, with sticky headers).
- Practice sessions are in the data but hidden in the app. Prossimi filters them with `isPractice` (`lib/format.ts`); Risultati only lists events that have a result, which practice sessions never do.
- `DATA_URL` in `lib/data.tsx` always points at the published GitHub Pages data, so the app does not see local importer output in `out/`.
- `YouTubePlayer` also derives its WebView origin from `DATA_URL`, because YouTube rejects embeds without a web origin. Changing `DATA_URL` therefore changes the player's origin too.
- `VideoCard` plays YouTube videos inline when they can be embedded and opens the YouTube app otherwise. A video with `url` (Sky Video) is not on YouTube: the card says "Guarda su video.sky.it ↗" on the thumbnail and opens the page with `expo-web-browser`, and the footer shows the site instead of YouTube.

### Expo guidance

`app/AGENTS.md` applies to app work. In particular, Expo changes between SDK releases, so check the docs for the SDK version in `app/package.json` rather than relying on memory. Run lint and typecheck before calling a task done. Native libraries not bundled in Expo Go require a development build, and `ios/`/`android/` are generated, so never edit them by hand.
